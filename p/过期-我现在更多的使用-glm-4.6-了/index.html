[过期] 我现在更多的使用 GLM 4.6 了

比较 GLM 4.6 与 DeepSeek v3.2 在实际使用中的体验差异

updated at: 2025-10-27 只有在很简单的任务上我才会使用 glm4.6。实际体验上，经常会出现小问题。例如使用 claude code 的时候无法更新文件。

这是近期使用 code agent 一些体会。

模型对比

在我的实际使用体验下来，相比于 DeepSeek v3.2，GLM 4.6 还是要更强一些。

例如，我在 nextjs 的项目中，创建了配置 nextjs config -> baseUrl 192.168.2.14:8080，GLM 4.6 在不提供明确上下文的前提下，能识别这个预先配置，但是 DeepSeek v3.2 无法做到。

但 GLM 4.6 并非全面领先的。在问题相对不确定的情况下，DeepSeek v3.2 更加保守，不会去突破我在任务完成时预先提出的限制。GLM 4.6 则视我的限制于无物，大胆的修改然后改崩。

工具

相比于在 claude code / cline 中使用 GLM 4.6，在 kilo code 中使用体验是最好的。

  • kilo code 可以并行读取文件，cc 只能串行一个个读取
  • kilo code 强制要求生成 plan，相比于 cc 对 big model 限制更多。
  • 可视化界面更好操作。我可以直接 ban 掉 python 命令（我需要执行 uv run 而不是直接执行 python 命令）

但是 kilo code 本身也有问题。无法使用 input; http 类型的 mcpServer。这使得 web-search-prime 在 kilo code 上无法使用。
