便宜且不留存：用 OpenRouter 路由 DeepSeek-V4-Flash

官方峰段涨到 $0.44/$1.32 之后，怎么继续便宜地用 deepseek-v4-flash：OpenRouter 上 17 个端点比价，路由参数 data_collection:"deny" 保证数据不留存，外加快照、量化、回退三个坑。2026-09-01 更新：SiliconFlow、百炼齐涨至官方价位，百炼 10-10 下线全部第三方模型——低价只剩 OpenRouter，与数据不出境二选一

DeepSeek 官方 API 从 2026-08-16 起峰谷分时计费。flash 峰段（北京时间 09:00–12:00、14:00–18:00）cache miss $0.44、output $1.32 per 1M（¥3.17/¥9.50），相对旧价 $0.14/$0.28 涨了 3 到 4.6 倍。我的用量，agent 会话和 cron 任务，全在峰段。

v4-flash 我用得很多，之前写过前缀缓存实测和 SiliconFlow 缓存阈值。这次给它找条出路，要求两条：比官方便宜，数据不留存（ZDR）。查下来 OpenRouter 能同时满足，中间踩了几个坑。

更新（2026-09-01）：国内平台涨到官方价位，低价只剩 OpenRouter

SiliconFlow 把 DeepSeek-V4-Flash 从固定价改成了峰谷分时，阿里云百炼 8-17 起也把 DeepSeek-V4-Flash-0731 调到同一张价目表。数据不出境的三个选项的新价（per 1M tokens，人民币，北京时间，2026-09-01 查证：SiliconFlow 价格页、百炼涨价公告、百炼模型页）：

百炼忙时档和 SiliconFlow 峰段逐分对齐，差的只是低价档窗口宽窄：百炼 10 小时、SiliconFlow 6 小时，都不如官方谷段宽。对照旧价，SiliconFlow 峰段输入涨 3.2 倍、输出涨 4.5 倍、缓存价涨 15 倍。

价格归价格，表里的差价已经小到没有意义：SiliconFlow/百炼高价档的输入输出只比官方便宜 5% 上下，缓存命中价反而贵 3 倍（¥0.30 对 ¥0.10），还叠加 >2K token 才可能命中的门槛；官方命中后 TTFT 明显下降，SiliconFlow 实测 9–104 秒波动、偶发 503。agent 这类缓存占大头的负载，官方有效单价更便宜也更稳。唯一没跟进的是 OpenRouter 上的 SiliconFlow 端点，2026-09-01 仍报 $0.13/$0.28、cache $0.028。

百炼还有更狠的一刀：7 月公告宣布 10 月 10 日下线全部第三方模型代理，配额从公告日起已在逐步收紧（下线公告、完整清单），覆盖：

  • DeepSeek V3/V3.1/V3.2/R1 全系
  • Kimi K2、MiniMax M2.1、GLM 4.6/4.7
  • qwen-turbo、qwen-coder-plus 等一大批千问旧型号

想靠百炼一站式聚合国产模型的路，也到头了。

现在拼图齐了。数据不出境的三个选项基本收敛到同一价位（差价 5% 以内），而官方缓存价只有另两家忙时档的 1/3、命中无门槛、TTFT 最低：不出境，直连官方就是最优解，再绕第三方没有任何价格意义。想要明显低于官方的价格，只剩 OpenRouter 上的第三方端点（DeepInfra $0.08/$0.18、DigitalOcean $0.068），代价是请求先过美国转发层。低价和数据不出境，现在只能二选一。文中 SiliconFlow 直连的 $0.13/$0.28 均为 2026-08-25 历史价格（OpenRouter 上其端点暂未跟进，仍 $0.13/$0.28）。

先说结论

DeepInfra 的 fp8 端点，$0.08/$0.18（¥0.58/¥1.30）per 1M，cache $0.016。比峰段新价便宜 5–7 倍，比涨价前的官方旧价 $0.14/$0.28 还便宜，同时 prompt 不留存在任何供应商。靠的是请求体里的三个路由参数（直接调 OpenRouter 的 body）：

参数管什么
data_collection: "deny"只路由不收集用户数据的 provider，ZDR 约束在这里落地
order: ["DeepInfra"]优先 DeepInfra，故障时回退，回退只落在同样过了 deny+fp8 过滤的端点里
quantizations: ["fp8"]锁原生 fp8 精度，排除二次量化的 fp4 端点

下面是推导过程。

17 个端点：都不训练，但 6 家留存 prompt

调 GET /api/v1/models/deepseek/deepseek-v4-flash/endpoints（2026-08-25 实测），v4-flash 一共 17 个端点。两个发现。

一是官方 DeepSeek 在 OpenRouter 上不供货 v4-flash，17 家全是第三方托管。这反而省了事：官方 provider（供 v4-pro 那些）是 training: true 加 retainsPrompts: true，ToS 允许去标识化后用于改进模型，「要官方 + 要不留存」本来就不成立，v4-flash 恰好没有官方端点。

二是 17 家全部 training: false，不会拿数据训练，但其中 6 家会留存 prompt（retainsPrompts: true）。不训练和不留存是两回事，ZDR 要的是后者（人民币按 7.2 汇率换算，下同）：

最便宜的三家 StreamLake、Baidu、GMICloud（$0.083–0.087）恰好全在留存名单里。只按价格 sort: price 路由的话，prompt 正好流进留存最积极的那几家，所以要先过滤再排序。

deny 过滤后剩 11 家 ZDR 端点，fallback 只在过滤后的候选集里选，漏不出去。v4-flash 也没有 :free 变体，不存在免费端点拿数据换的坑。另一个语义接近的开关是 provider: {zdr: true}，按零留存认证过滤，跟 deny 二选一就行。

OpenRouter 自己呢？默认不存 prompt/response。两个 opt-in（私有 Input/Output Logging、用数据换 1% 折扣）默认都关。token 数、延迟这类 metadata 必存，匿名采样的 prompt 分类关不掉但不关联账号，一般可以接受。

三个坑

alias 指的是旧权重

deepseek/deepseek-v4-flash 这个 alias 当时指 0423 权重，而官方 api.deepseek.com 08-13 已经静默切到 0731。用 alias，你以为和官方一样，实际是三个月前的旧权重。要同样的权重就写死快照：

● ● ●text
1

deepseek/deepseek-v4-flash-0731

更便宜的 fp4，精度再砍一半

0731 快照下还有 open-inference/fp4 端点，$0.03/$0.10，比 DeepInfra 又便宜一半多。但 fp4 是在原生 fp8 基础上再砍一半精度的二次量化，质量说不好，我用 quantizations: ["fp8"] 锁住。这个过滤靠端点自报的 quantization 字段，个别端点标 unknown（DigitalOcean、Phala），会被一并排除，宁可少几家也不放进未知精度。

用 order，别用 only

only: ["DeepInfra"] 硬锁，DeepInfra 一故障整条 channel 直接失败。order: ["DeepInfra"] 优先 DeepInfra，故障时回退到同样过了 deny+fp8 过滤的端点（AkashML、CoreWeave、Parasail 等，$0.14/$0.28 档），约束不破。

速度参考（同 prompt 实测，2026-08-25）：官方直连最快，输入 ~3683 tok/s，TTFT 0.95s；SiliconFlow 居中，~2700，1.29s；多一层网关再慢一点，~2436，TTFT 加 ~0.5s。OpenRouter 也是转发层，开销差不多这个量级，便宜是拿一次转手换的，延迟敏感就自己权衡。

残余风险

  1. ZDR 不等于数据不出境，这条约束得分方向说。要求数据不出境（国内合规）的话，OpenRouter 帮不上忙：请求先过它的转发层（美国公司），就算最终落在中国区的 SiliconFlow 端点，也出了一趟境。这种需求只能直接调 SiliconFlow 的 API——它已涨到官方峰段价位（见文首更新），等于为合规付溢价（缓存实测）。反过来要求数据不进中国的话，deny 之后 SiliconFlow 还在集合里（中国区基础设施，Baidu 和 Alibaba 倒是被留存过滤自然排掉了），加 ignore: ["SiliconFlow"]。
  2. 第三方端点不等于官方行为。各家量化版本可能不同，上下文长度也不一致（多数 1M，个别 384K）。响应波动可以参考 SiliconFlow 的前科：TTFT 9s~104s，偶发 503。
  3. ZDR 名单是动态的。调研这几天亲眼看到 endpoints API 收紧（留存字段从有到无）、ZDR 集合变化（AtlasCloud 掉出名单）。别把名单硬编码，用 GET /api/v1/endpoints/zdr 拉活数据；自动化接入的话，部署时断言响应里的 provider_name 在实时 ZDR 集合里，不在就当致命错误退出。
